# AGENTS.md — read this before touching anything 🤖

> ## ⚠️ WARNING: THIS CODEBASE IS VIBE-CODED ⚠️
>
> Large parts of GramGuru were generated by an LLM in a single, enthusiastic
> session. It is **not** battle-tested. It converts recipe units; it will not
> file your taxes, but it _might_ mis-handle an exotic unit. Always run the
> tests after changing anything, and read diffs before trusting them.

## What this is

A Firefox Manifest V3 extension that scans page text for recipe units (Norwegian
and imperial) and annotates them with the equivalent weight in grams.
No runtime network access; the density table is bundled.

## Golden rules

1. **Plain JavaScript, no build step.** The files under `src/` are exactly what
   ships. No TypeScript, no bundler, no transpiler, no minifier. Import with
   explicit `.js` extensions in source (`import { x } from "./y.js"`).
2. **No npm dependencies. Ever.** Use Node built-ins only.
3. **Keep it small.** This is the whole point of the project.
4. **Never commit secrets.** `.env` is git-ignored.
5. **The AMO answer is "No build tools."** Don't reintroduce anything that
   processes source into shipped files, or this changes.
6. **Do not spam the AMO API.** It hard-throttles per account: HTTP `429` with a
   `Retry-After` that escalates fast (minutes → **~18 hours** after a burst).
   Run `scripts/publish.js` / `scripts/upload-media.js` **once**, never in a
   retry loop, and space out media writes. If you get a `429` with a long retry,
   **STOP and wait** — do not keep hammering it (that's what lengthened the
   ban). `upload-media.js` already bails out instead of sleeping for hours.

## Layout

```
manifest.json          MV3 manifest. Name: "GramGuru 🧐".
content-loader.js      Classic content script that dynamic-imports src/content.js
                       (Firefox content scripts can't be ES modules directly).
content.css            Inline marker + tooltip styles.
popup.html             Popup shell; loads src/popup.js as a module.
src/convert.js         PURE converter (no DOM). Shared by content script + tests.
src/data.js            Committed matprat (Norwegian) density table.
src/english.js         Committed USDA FoodData Central (English) density table.
src/content.js         DOM glue: walk text, wrap matches, badge count.
src/background.js      Sets the toolbar badge from the content-script count.
src/popup.js           The one switch.
scripts/build-data.js  Optional: fetch matprat -> src/data.js.
scripts/build-english.js Optional: download USDA SR Legacy -> src/english.js.
scripts/e2e.js         Headless-Firefox end-to-end test (WebDriver BiDi).
scripts/package.js     Zip the extension -> web-ext-artifacts/.
scripts/publish.js     AMO Submission API v5 upload + publish (JWT).
tests/                 node:test suites. Pure tests + live recipe-page tests.
```

## Testing notes

- `tests/convert.test.js` — pure unit tests. Add a case for every new unit,
  plural form, or scaling rule. This is the file that keeps us honest.
- `tests/sites.test.js` — fetches real recipes
  (<https://www.matprat.no/oppskrifter/tradisjon/leverpostei/> and a meny.no
  recipe), pulls `recipeIngredient` from the page's `application/ld+json`, and
  asserts the grams. Falls back to `tests/fixtures/` when offline.
- `scripts/e2e.js` — the real deal. Launches headless Firefox, installs the
  extension as a temporary add-on over WebDriver BiDi (`ws://127.0.0.1:<port>/session`),
  then asserts the injected `.gg` marks on `devtest/testpage.html` and both real
  recipe sites. The content script must match across inline-element boundaries
  (recipe sites split `1,5` / `dl` / `melk` into separate `<span>`s), so
  `src/content.js` flattens each leaf block's inline text before converting and
  marks groups of spans with a shared `data-gg-id`. Keep that invariant.
- Hover text (`buildNote()` in `src/convert.js`):
  known → `3 ss hvetemel = 27 g (exact) 🧐`; imperial → `… 🔪 death to imperialism`;
  **unknown** → a match with `unknown: true`, `metric: ""`, and the original kept.
  Volume units also get `estimates` `{liquid, dry}` (water vs wheat flour).
- On the page (`src/content.js` `makeSpan()`): known → the metric value; unknown →
  class `gg-unknown` with the estimates inline (`30/18 g wet/dry`) for volume, or
  unknown **count** units are ignored (prose false positives like "8.657 pakker").
  Marks add **no underline** — only a
  background tint + emoji badge — so they don't fight the page's own styling.
  Estimates are short-numbered (no decimals ≥ 20 g) and the tooltip is two lines
  (`30 g if wet` / `18 g if dry`), rendered via `white-space: pre-line`.
- The inline marker emoji comes from `match.marker` via CSS `attr(data-gg-marker)`
  so it always matches the tooltip: `🧐` exact / `🔪` imperial / `🤷` unknown.
- Unit handling (`unitKind()`): **count** units (stk, pk, skive, neve, fedd, bunt,
  boks, stick) are never guessed. **Volume** units (l, dl, ss, ts, kopp, ...) get
  water/flour estimates when unknown. **Mass** units (oz, lb) are exact constants.
  Ingredient capture also looks at the adjacent flex/grid cell (tine.no puts
  amount and ingredient in separate cells) and uses compound-word suffix matching
  (lettmelk → melk).
- Ingredient index = matprat (Norwegian) + curated English aliases + USDA
  `src/english.js` (fills gaps; earlier sources win). `scripts/build-english.js`
  downloads the ~6 MB USDA SR Legacy CSV and regenerates `src/english.js`.

## Extending the data

`scripts/build-data.js` uses **matprat.no only**. The plan noted
matvaretabellen.no (`https://www.matvaretabellen.no/api/nb/foods.json`) as a
future fallback source. If you add it, keep `src/data.js` shape stable
(`[{ n: name, u: { unitKey: gramsPerUnit } }]`).

## Releases & pull requests

- **Every new version goes through a pull request.** Create a feature branch,
  commit, push it, open a PR (`gh pr create`), and **auto-merge** it
  (`gh pr merge --squash --delete-branch`) unless told otherwise.
- **Branches → beta.** Pushing a non-`main` branch runs `.github/workflows/beta.yml`:
  package a beta, publish it to the **unlisted/beta** add-on, refresh the **rolling**
  prerelease Release tagged `beta` (stable `updates.json` + `gramguru-beta.xpi` URLs),
  and create a per-build prerelease `v<core>-beta.<n>` holding the signed XPI.
- **`main` → release.** Merging to `main` runs `.github/workflows/release.yml` and
  publishes the `manifest.json` version to the **listed** channel. Stable releases
  live on **Mozilla only** — no GitHub Release/tag is created for them (GitHub
  Releases are for beta pre-releases; GitHub also attaches the source archives).
- **Versioning (hybrid — read this):** AMO/MV3 requires `manifest.version` to be
  1–4 dot-separated numbers, ≤9 digits, **no letters or hyphens** (verified:
  `0.1.13-beta.3` is rejected — _"should be simplified"_). So a semver pre-release
  **cannot** be the manifest version. Instead:
  - **Release:** `manifest.json` is plain semver `MAJOR.MINOR.PATCH`.
  - **Beta:** manifest `version` = `<core>.<run_number>` (MV3-legal, numeric,
    monotonic); the GitHub **tag/Release** is `v<core>-beta.<run_number>` — that's
    the semver pre-release (semver.org item 9).
- Required repo secrets: `AMO_API_KEY`, `AMO_API_SECRET`, `AMO_ADDON_ID`
  (listed), `BETA_ADDON_ID` (unlisted). Never commit these. Nothing under
  `web-ext-artifacts/` or `beta/` is committed — beta artifacts go to GitHub Releases.
- Required repo secrets: `AMO_API_KEY`, `AMO_API_SECRET`, `AMO_ADDON_ID`
  (listed), `BETA_ADDON_ID` (unlisted). Never commit these. There is no
  `web-ext-artifacts/` or `beta/` committed — artifacts go to GitHub Releases.

## Publishing

See README "Publish to addons.mozilla.org". `scripts/publish.js` reads
`AMO_API_KEY`, `AMO_API_SECRET`, `AMO_ADDON_ID` (run with `node --env-file=.env`).
It creates the listing if it doesn't exist yet, otherwise adds a version.

Beta channel (unlisted/self-distributed): built with `node scripts/package.js --beta`
(id `gramguru-beta@anderss`; `update_url` → the `beta` release's `updates.json`).
`scripts/publish.js --channel unlisted` (`AMO_ADDON_ID=gramguru-beta@anderss`)
downloads the AMO-signed XPI to `web-ext-artifacts/gramguru-beta.xpi` and records
`{version, update_link}` in `updates.json`, where `update_link` is the `beta`
release asset (`BETA_XPI_URL`). Both are then uploaded with
`gh release upload beta updates.json web-ext-artifacts/gramguru-beta.xpi --clobber`
— **nothing is committed to git**. Firefox keeps the `update_url` baked into the
installed version, so it must ship in the first build; unlisted signing is async
(`unreviewed` → `public`, `.zip` → `.xpi`). Hosting URLs live in `scripts/repo.js`.
